# بانک متن‌های فارسی

**هدف:** همهٔ متن‌های فارسی پروژه یک‌جا و با شناسهٔ ثابت باشد تا مالک بتواند یک‌باره آن‌ها را به GPT یا Gemini بدهد، فارسی‌شان را درست کند و یک‌باره برگرداند، و Claude دقیقاً بداند هر متن را کجا بگذارد. (تصمیم مالک ۸ اکتبر، B49.)

## چه چیزی در بانک است (۱۵۸ متن، ۸ اکتبر)

عنوان گره‌ها، سرزمین‌ها، مناطق و مرحله‌ها؛ توضیح‌های مفهومی گره‌ها (`plain_fa`، سطح‌های D2 تا D4)؛ متن‌های کارت آموزشی قرقره (سه سطح سنی).
**هنوز در بانک نیست:** متن‌های بازی فعلی (`src/simple-machines`)، متن‌های کارت بندر، منو، آموزش بازی، رابط اسکیس، صفحهٔ معلم. هر منبع تازه با افزودن یک بخش در `sources()` داخل `tools/text_bank.py` وارد می‌شود (فهرست کارهای آینده).

## جریان کار (چهار گام)

1. **Claude:** `python3 tools/text_bank.py collect` ← `python3 tools/text_bank.py export`. خروجی: `docs/texts/export/texts_for_review_<تاریخ>.json` (دستور ویراستار هم داخل فایل است).
2. **مالک:** فایل JSON را به GPT یا Gemini می‌دهد (فایل را پیوست کند و بنویسد: «طبق `_instructions_fa` درون فایل عمل کن و فقط JSON برگردان»). خروجی را ذخیره و به Claude می‌دهد.
3. **Claude:** `python3 tools/text_bank.py import فایل-برگشتی.json` (بدون `--apply`) ← گزارش `docs/texts/IMPORT_REPORT.md`: چه چیز عوض شد، و آیا عدد/فرمول/برچسب HTML دست خورده یا واژهٔ ممنوع آمده. مشکل‌ها را به مالک نشان می‌دهد.
4. **Claude:** پس از تأیید مالک `--apply`: متن‌ها در بانک (وضعیت `reviewed`) و دقیقاً در جای خودشان در منبع‌ها نوشته می‌شوند؛ نسخهٔ قبلی بانک در `docs/texts/history/` می‌ماند. «تأیید نهایی» (`approved`) فقط با گفتهٔ مالک.

## قواعدی که ابزار می‌پاید

- شناسه‌ها و ساختار فایل دست‌خورده نباشد؛ فقط `new_text`.
- عدد، فرمول و برچسب‌های HTML عیناً بماند.
- واژه‌های ممنوع (`banned`) و واژه‌نامه (`glossary`) در فایل صادرشده هست: «نیرو» نه «زور»، «مسافت» نه «راه بیشتر»، «نیوتون»، و مانند آن.
- هر متن `kind`، `where` (کجا در بازی) و `context` دارد تا ویراستار بداند چه می‌نویسد.

## فایل‌ها

| فایل | کار |
|---|---|
| `TEXT_BANK_FA.json` | بانک اصلی (شناسه، متن، جای دقیق در منبع، وضعیت) |
| `PROMPT_FOR_REVIEWER_FA.md` | دستور آمادهٔ ویراستار (داخل خروجی گذاشته می‌شود) |
| `export/` | خروجی‌های آمادهٔ GPT/Gemini |
| `IMPORT_REPORT.md` | گزارش آخرین وارد کردن |
| `history/` | نسخه‌های قبلی بانک |
| `tools/text_bank.py` | ابزار (collect, export, import, apply, check) |

وضعیت‌ها: `draft` (موقت) ← `reviewed` (ویراستار بیرونی، منتظر مالک) ← `approved` (مالک).

## قرارداد برای هر مؤلفهٔ تازه (B50)

کنار هر کارت، مرحله، منو یا صفحهٔ تازه فایل `strings.fa.json` بگذار:

```json
{
  "card.pulley.title": {"text": "…", "kind": "title", "where_fa": "عنوان کارت قرقره", "context_fa": "…", "band": "همه"}
}
```

کد یا HTML فقط شناسه را می‌خواند (`S['card.pulley.title'].text`) و متن را در خود ندارد. `collect` این فایل‌ها را خودکار در بانک می‌ریزد (پوشه‌های `design/`، `src/`، `pilot/`)، و `import --apply` متن بازنویسی‌شده را در همان فایل می‌نویسد. رفت‌وبرگشت با هوش دیگر **فعلاً لازم نیست**؛ پس از تکمیل همهٔ کارت‌ها، مرحله‌ها، جعبه‌ها و آموزش بازی انجام می‌شود.
