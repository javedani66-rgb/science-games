# نظر پیاده‌سازی (طراح UI) دربارهٔ تحویل هنرمندان v5

نظر طراح است، نه شاهد کودک. دارایی‌ها هنوز وجود ندارند (`team/assets/` خالی)؛ ارزیابی بر پایهٔ سند سبک، دستور کار و v3/v4 است. هیچ سنجش سرعت روی گوشی ضعیف انجام نشده.

## ۱) کافی و سازگار است؟ نه کاملاً
**مانع‌ها**
1. **ناسازگاری ساختار نقشه.** v3 یک نقشهٔ DOM با ۳۴ گره (ریسمان)، ۹ قاب زمین و چینش زیگزاگ با درصد CSS است (`frameHTML`، `XF`، `mappath.js`). دارایی v5 یک بوم ثابت ۳۹۰×۲۴۰۰ با ۱۲ گره و مختصات ثابت است. این دو یکی نمی‌شوند. باید روشن شود ۳۴ گره چگونه به ۱۲ بنا نگاشت می‌شوند یا نقشه واقعاً ۱۲ گره می‌شود (سؤال ۱).
2. **inline شدن با `build.py` فعلی کار نمی‌کند.** `build.py` هر SVG را base64 داخل `url()` در CSS می‌گذارد. SVG داخل `url()` به `var(--l-*)`، `data-light` و کلاس‌های صفحه دسترسی ندارد، پس نور سه‌حالته و حالت‌های شخصیت کار نمی‌کند. باید SVG خام داخل DOM (sprite از `<symbol>`) بیاید. دلیل دوم: base64 حدود ۳۳٪ حجم اضافه می‌کند.
3. **حالت شخصیت با `.s-<state>` روی ریشه، از داخل `<use>` کار نمی‌کند.** سلکتور بیرونی از مرز `<use>` رد نمی‌شود و فقط متغیرهای CSS رد می‌شوند. شخصیت باید حالتش را با `--show-happy` و مانند آن بگیرد، یا من برای هر نمونه SVG را باز می‌کنم (حجم بیشتر).
4. **برخورد شناسهٔ `id`.** وقتی چند SVG در یک صفحه می‌آیند، `clipPath`، `gradient` و `filter` با نام تکراری روی هم می‌افتند. پیشوند یکتا برای هر فایل لازم است (`n03-clip`).
5. **دکمه، چیپ، پلاک و برگه به‌صورت SVG با اندازهٔ ثابت** با طول متن متغیر (فارسی، RTL) نمی‌سازد. 9-slice برای `<svg>` در CSS کم‌دردسر نیست. این‌ها را با CSS (توکن‌ها، شعاع 18/7 با ویژگی‌های منطقی، لبهٔ زیرین 6) خودم می‌سازم. فقط آیکون‌ها، قرص سختی، قفل و بناها SVG بمانند.

**کم است**
- `assets.json` (مانیفست): نام فایل، viewBox، نقطهٔ لنگر، اندازه، فهرست `id` لایه‌ها.
- `slots.json` برای هر گره: مختصات جای قرص سختی (بالا-راست)، قفل (پایین-راست)، مرکز پایه، پای b1، برچسب.
- `zones_bg` به‌صورت نوارهای هر زمین که بالا و پایینشان بدون درز به هم بچسبند، نه یک عکس ۲۴۰۰.
- صحنهٔ بازی: در v3 نمودار قرقره با JS رسم می‌شود (خط ۴۵۳ قالب) و فلش‌ها پویا هستند. SVG صحنه باید قطعه‌های جدا با `id` و مبدأ چرخش بدهد (طناب، تور، قرقره) وگرنه فقط پس‌زمینه می‌شود.
- جهت آیکون‌ها: «برگرد/بعدی» یک فلش بدهند با قرارداد «رو به انتهای خط». معکوس‌سازی را خودم می‌کنم.
- **حجم:** فونت‌ها حدود ۱۱۸KB (۱۶۰KB با base64). v3 فعلی ۷۶۴KB تا ۱٫۱MB است، SVGهای کیت v3 حدود ۳۲۸KB خام. با سقف‌های فعلی (۱۲ بنا ≤۲۵KB = ۳۰۰KB، b1 ۲۵KB، ۷ سر، آیکون‌ها، سه صحنه، سه هنر کارت، کاشی‌ها) به ۲٫۵MB می‌رسیم، ولی «کل هر پوشه ≤۱٫۵MB × ۵ هنرمند» از بودجهٔ ۲٫۵MB بیشتر است. پیشنهاد: بودجهٔ ساخت‌یافته (بنا ۳۰۰، شخصیت ۳۰۰، رابط ۲۰۰، نقشه و زمین ۴۰۰، کارت و صحنه ۵۰۰، فونت ۱۶۰، کد ۳۰۰) و `build.py` اگر از ۲٫۵MB گذشت خطا بدهد.

## ۲) خطرها
- **فیلتر brush:** `feTurbulence`+`feDisplacementMap` روی DOM زنده در اسکرول نقشهٔ بلند روی اندروید ضعیف گران است؛ v4 آن را روی گروه‌های بزرگ با ناحیهٔ ۷۹۰×۲۸۰۰ و scale 60 و blur داشت. «پیش‌رندر» باید یعنی **جابه‌جایی در مسیرها یک بار بیرون پخته شود** (یا تصویر)، نه فیلتر در مرورگر. من فقط با 4× کند شدن CPU آزمون می‌کنم.
- **درخشش شب:** فقط `box-shadow`/`text-shadow` ثابت دور قاب؛ بدون `filter: drop-shadow` روی لایهٔ بزرگ و بدون blur پویا. پنجره‌ها فقط تغییر opacity.
- **انتقال روز/غروب/شب:** متغیر CSS ثبت‌نشده نرم تغییر نمی‌کند، رنگ پرش می‌کند. دو راه: `@property` برای توکن‌ها (پشتیبانی گوشی‌های قدیمی نامعلوم)، یا لایه‌های جدا با opacity (آسمان، آب، rim). پیشنهاد دوم. همچنین نقشه (روز) و محیط (شب) دو صفحهٔ جدا هستند و ۱٫۲ ثانیه باید هر دو در DOM بمانند؛ بازگشت هم همین. v4 از `mix-blend-mode` استفاده می‌کرد که سند ممنوع کرده.
- **RTL:** مختصات SVG آینه نمی‌شود؛ «بالا-ابتدای خط» در هنر یعنی راست فیزیکی و در CSS باید منطقی باشد. نور بالا-چپ فیزیکی ثابت است (درست). ارقام «۱ تا ۲» در `bdi dir=rtl`. متن داخل SVG با `direction` ارث‌بری می‌کند و `anchor` برعکس است (قاعدهٔ CLAUDE.md).

## ۳) ترتیب کار پیشنهادی روی v3 (هر گام یک ساخت و عکس ۳۹۰×۸۰۰ و ۳۶۰×۶۴۰)
0. `build.py` جدید: sprite، پیشوند `id`، خروجی خام، حدّ حجم، ادغام `tokens.css`؛ با جاگذار (بدون هنر).
1. توکن‌ها روی `kit.css` (نگاشت رنگ قدیم به جدید)، فونت‌ها، نوار بالا، دکمه، چیپ، برگه، قرص سختی. همهٔ صفحه‌ها بدون هنر جدید رنگ و شکل نو می‌گیرند.
2. نقشه: زمین‌ها، مسیر دولایه (مسیر را `mappath.js` می‌سازد؛ فقط ضخامت‌ها 6/22)، بناها، b1، «اینجایی».
3. منو و کاشی‌ها، کارت‌دان و قفسه.
4. صفحهٔ محیط (پشتهٔ ۳ کارت شب) و کارت درس.
5. صحنهٔ بازی.
6. آخر از همه: انتقال نور و `data-light`، سپس `ov.py` و آزمون خاکستری.

## ۴) چهار درخواست مشخص
1. **بخش ۷ و قاعدهٔ مشترک دستور کار:** هر هنرمند یک `sprite_<دسته>.svg` از `<symbol>` + `assets.json`؛ شناسه‌ها با پیشوند فایل؛ حالت‌ها با متغیر CSS نه کلاس ریشه؛ بدون ارجاع بیرونی.
2. **بخش ۲-ب و ردیف ۱۲ جدول بخش ۰ (brush):** اثر brush در هندسه پخته شود و خروجی بدون فیلتر زنده باشد؛ نسخهٔ فیلتری فقط پشتیبان.
3. **بخش ۵ و دستور کار env (`zones_bg`، `node_*`):** نوارهای زمین بدون درز + `slots.json`؛ و جدول نگاشت گره به بنا (با مدیر/مالک).
4. **بخش ۴ (نور) و دستور کار ui:** دکمه/چیپ/پلاک/برگه به‌صورت مشخصات CSS (توکن، شعاع، لبه) نه SVG ثابت؛ و لایه‌های `rim`، `shade`، `windows` با `id` ثابت برای تغییر با opacity.

## ۵) سؤال‌های باز
1. نقشهٔ v5 ۱۲ گره است یا ۳۴ گرهٔ ریسمان v3 با ۱۲ بنای تکراری؟ (تأثیر مستقیم بر ساخت.)
2. سقف ۲٫۵MB کجا تعریف شده و فونت‌ها و کد را شامل می‌شود؟ در اسناد خوانده‌شده نیافتم.
3. نمودارهای JS صحنه (قرقره، فلش‌ها) به سبک خط جدید تغییر کنند یا هنر صحنه جایگزین شود؟
4. حداقل گوشی هدف و آستانهٔ قبول (مثلاً ۳۰fps در 4× CPU throttle)؟
5. گروه نمایش نقشه: v4 سه چیپ پایه بالا دارد، v3 ندارد؛ کدام؟
6. نوار بالای ۸۶px روی نقشه گره‌ها را می‌پوشاند؟ (باید در ماکت دیده شود؛ فعلاً نمی‌دانم.)
